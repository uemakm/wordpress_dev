# 環境構成

## 目的と範囲

- WordPress本体、既存プラグイン、自作プラグインの動作確認
- 自作プラグインの実装とデバッグ
- PHPやWordPressのバージョンを変えた互換性確認
- 将来の自動テスト導入

公開サーバーへの配置、本番データの移行、本番環境の構築は対象外です。

## 構成

```text
Apple Silicon Mac
├── Node.js / npm
├── ソースコード・環境設定
└── Docker Desktop
    └── wp-envが管理するコンテナ
        ├── 開発用WordPress（PHP・Webサーバー）とDB
        ├── テスト用WordPress（PHP・Webサーバー）とDB
        └── CLI・テスト用ツール
```

| 項目 | 方針 |
| --- | --- |
| コンテナ実行環境 | Docker Desktop（Apple Silicon版） |
| WordPress環境管理 | @wordpress/envをプロジェクトの開発依存として導入 |
| WordPress | 7.1.4をcore設定で固定 |
| PHP | 初期案は8.3。公開先や対象プラグインの要件に合わせて変更 |
| DB | MariaDB 12.3.3を設定で固定 |
| 開発サイト | http://localhost:8888 |
| テストサイト | http://localhost:8889 |
| デバッグ | WP_DEBUG・ログを有効化。画面へのエラー表示は無効化 |
| ソース管理 | Git。npmのpackage-lock.jsonも管理 |

PHP・DBはコンテナ内で動かすため、Macへ直接インストールする必要はありません。通常は独自のcompose.yamlを作成せず、wp-envで管理します。

## Docker Desktopの採用理由

MacではDocker CLIだけをインストールしてもLinuxコンテナは動きません。Linux仮想環境とDocker Engineなどを提供する実行環境が必要です。

Docker Desktopはそれらと管理画面をまとめて導入でき、起動状態や問題を確認しやすいため採用します。wp-envがDocker Desktop固有の機能を必要とするわけではありません。Colima＋Docker CLIなどへの変更も可能ですが、その場合は接続・ファイル共有・起動を改めて確認します。

## ローカル環境の確認結果

2026-11-14に確認した状態です。

- CPUアーキテクチャ：arm64
- Node.js・npm：PATH上にコマンドあり。バージョン適合は未確認
- Docker・PHP：PATH上にコマンドなし。アプリ自体の有無は未確認
