# ディレクトリ構成案

## 提案

環境設定はルート、自作コードは01.plugins、説明資料は00.ドキュメントにまとめます。以下は完成時の案です。共通設定・npm依存・01.plugins・02.検証成果物まで作成済みです。sample-pluginは将来の例で、まだ作成していません。

```text
環境構築/
├── README.md
├── AGENT.md                     # 作業方針
├── AGENTS.md                    # エージェント向け入口
├── .gitignore
├── .wp-env.json                 # 共通の環境設定
├── .wp-env.override.json        # 個人用の上書き設定（Git対象外）
├── package.json                 # wp-envの依存・起動コマンド
├── package-lock.json            # npm依存の固定
├── 01.plugins/
│   └── sample-plugin/           # 実際のプラグイン名で作成
│       ├── sample-plugin.php    # プラグインヘッダー・初期化
│       ├── includes/            # PHP処理。必要になったら追加
│       ├── assets/              # CSS・JavaScript・画像
│       └── tests/               # プラグイン固有のテスト
├── 00.ドキュメント/
│   ├── 01.環境構成.md
│   ├── 02.ディレクトリ構成案.md
│   ├── 03.構築・運用手順.md
│   └── 04.構築・検証記録.md          # 構築結果・検証条件と結果（後で作成）
├── 02.検証成果物/                   # DBエクスポート・ログなど（Git対象外）
└── 03.初期データ/
    ├── README.md
    └── 01.サンプル記事.php
```

03.初期データ/にはGit管理する投入スクリプトと説明を配置します。`npm run seed`で実行できます。

## 運用ルール

- 最初はプラグイン1個から開始し、必要になったフォルダだけ追加します。
- 自作プラグインは1プラグイン1フォルダとし、wp-envのplugins設定に個別に登録します。
- WordPress本体、DB実体、コンテナのデータはwp-envに管理させ、リポジトリに複製しません。
- 外部プラグインは原則としてソースをこのリポジトリへコピーせず、導入元・バージョンを設定や検証記録に残します。有料プラグイン等の配布物はGitに入れません。
- .gitignoreにはnode_modules/、.wp-env.override.json、02.検証成果物/、.DS_Storeなどを設定します。
- package-lock.jsonと共通の.wp-env.jsonはGitで管理します。
- 認証情報やライセンスキーは文書・共通設定へ記載しません。
- WordPress・PHPのバージョンを変更する前に、必要なDBを退避して検証条件を記録します。

複数の独立した案件でWordPressやPHPのバージョンを同時に変える必要が出たら、案件ごとに環境ルートを分けます。初期段階では単一環境で管理します。

## 命名方針

任意の文書・フォルダは番号付きの日本語名を優先します。ツールが自動認識する設定ファイルは標準名を維持し、プラグインのスラッグや内部ファイルは半角名を基本とします。詳細は[AGENT.md](../AGENT.md)を参照してください。
