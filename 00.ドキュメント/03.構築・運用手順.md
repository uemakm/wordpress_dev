# 構築・運用手順

Windowsでは先に[Windows構築手順](06.Windows構築手順.md)を参照し、WSL 2とDocker Desktopを準備してください。この文書の導入例はMacを基準としています。

以下は再構築のための手順です。実際の構築結果・差異は[構築・検証記録](04.構築・検証記録.md)を参照してください。

## 1. 前提条件の確認

作業ルートでNode.js・npmのバージョンを確認し、導入するwp-envが要求するNode.jsのバージョンを満たすか確認します。

```bash
node --version
npm --version
npm view @wordpress/env engines
```

8888・8889番ポートが他のアプリで使用されている場合は、設定を変更します。

## 2. Docker Desktopの導入

[公式手順](https://docs.docker.com/desktop/setup/install/mac-install/)に従いApple Silicon版を導入・起動します。初回設定後、次を確認します。

```bash
docker version
docker info
```

CLIだけでなくDocker Engineに接続できることを確認します。

## 3. wp-envの導入

作業ルートで実行します。

```bash
npm init -y
npm install --save-dev --save-exact @wordpress/env
mkdir -p 01.plugins
```

package.jsonとpackage-lock.jsonをGit管理します。

## 4. 共通設定の作成

ルートに.wp-env.jsonを作成します。最初はプラグインを登録せず、WordPress単体の起動を確認します。

```json
{
  "phpVersion": "8.3",
  "port": 8888,
  "testsPort": 8889,
  "config": {
    "WP_DEBUG": true,
    "WP_DEBUG_LOG": true,
    "WP_DEBUG_DISPLAY": false
  }
}
```

この設定ではWordPressのバージョンは未固定です。構築時に実際のバージョンを確認し、wp-envのcore設定で固定します。設定方法は[公式仕様](https://developer.wordpress.org/block-editor/reference-guides/packages/packages-env/)を参照します。

## 5. 起動と確認

```bash
npx wp-env start
```

初回はイメージなどの取得に時間がかかります。

- 開発管理画面：http://localhost:8888/wp-admin/
- テスト環境：http://localhost:8889/

初期ログイン情報はwp-envの起動出力・公式仕様で確認します。開発サイトの日本語設定、投稿作成、画像アップロードを確認します。停止・再起動後も投稿と設定が保持されることを確認し、結果を00.ドキュメント/04.構築・検証記録.mdへ記録します。

## 6. プラグインの追加

01.plugins/sample-plugin/sample-plugin.phpに有効なプラグインヘッダーを持つPHPファイルを作成してから、.wp-env.jsonへ以下のキーを追加します。sample-pluginは実際の名前に置き換えます。

```json
"plugins": ["./01.plugins/sample-plugin"]
```

設定変更を反映します。

```bash
npx wp-env start --update
```

管理画面でプラグインの認識・有効化を確認し、ソース変更が反映されることを確認します。自動テストはプラグインの仕様が決まってから追加します。

## 日常操作

```bash
# 起動
npx wp-env start

# 停止（通常の作業終了）
npx wp-env stop

# ログ確認
npx wp-env logs

# 開発環境のWordPressバージョン確認
npx wp-env run cli wp core version
```

通常の作業終了にはstopを使います。DBのリセットや環境の破棄はデータを失う操作なので、必要なデータの退避後に個別に実施します。

コンテナやDBはGitの管理対象ではありません。ソースのコミットだけでは投稿・設定・アップロード画像のバックアップにならないため、残したい検証データは別途エクスポート・退避します。

## サンプル記事の再投入

Gitから取得した環境では`npm ci`で依存を導入し、`npm start`で起動した後、次を実行します。

```bash
npm run seed
```

03.初期データのスクリプトから開発環境へ30記事を投入します。既存のスラッグはスキップします。初期データの共有設定を既存環境に追加した際は、先に`npm start -- --update`を実行してください。詳細は[初期データの説明](../03.初期データ/README.md)を参照してください。
