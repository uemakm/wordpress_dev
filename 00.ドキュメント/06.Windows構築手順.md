# Windows向け構築手順

公式資料確認日：2026-11-15。Windows実機での動作確認は未実施です。

## 採用する構成

Windows 11＋WSL 2（Ubuntu）＋Docker DesktopのWSL 2バックエンドを推奨します。WindowsのブラウザからWordPressにアクセスし、Git・Node.js・npm・wp-envはUbuntu側で実行します。

WordPress公式もWindowsではDocker DesktopのWSL 2バックエンドを推奨しています。[wp-env導入ガイド](https://developer.wordpress.org/block-editor/getting-started/devenv/get-started-with-wp-env/)

```text
Windows 11
├── ブラウザ（localhost:8888 / 8889）
├── Docker Desktop（WSL 2バックエンド、Linuxコンテナ）
└── WSL 2 / Ubuntu
    ├── Git・Node.js・npm
    └── ~/projects/wordpress_dev
        └── wp-env → WordPress・PHP・MariaDBコンテナ
```

Docker DesktopはWindows側に導入します。Ubuntu側に別のDocker Engineを追加すると競合するため、この手順では導入しません。[Docker公式](https://docs.docker.com/desktop/features/wsl/)

## 1. Windowsと仮想化の確認

Docker Desktopの対応するWindows・CPU・メモリ要件と、BIOS/UEFIのハードウェア仮想化が有効であることを確認します。Windowsのシステム情報でOSとCPUを確認し、CPUに合うインストーラーを選びます。

WSLが導入できるOSと、現在のDocker Desktopのサポート対象OSは同じではありません。詳細は[Docker DesktopのWindows要件](https://docs.docker.com/desktop/setup/install/windows-install/)を確認してください。この手順ではWindows 11を対象とします。

## 2. WSL 2とUbuntuの導入（Windows PowerShell）

初回は管理者としてPowerShellを開きます。

```powershell
wsl --install -d Ubuntu
```

必要に応じてWindowsを再起動し、Ubuntuを起動してLinux用ユーザー名とパスワードを設定します。既にUbuntuがある場合は再インストールせず、次で状態を確認します。

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

UbuntuのVERSION列が2であることを確認します。1の場合は、必要なデータをバックアップしたうえで変換します。

```powershell
wsl --set-version Ubuntu 2
```

ディストリビューション名がUbuntu以外の場合は一覧に表示された名前へ置き換えます。[Microsoftの導入手順](https://learn.microsoft.com/en-us/windows/wsl/install)

## 3. Docker Desktopの導入（Windows）

[Windows向け公式ページ](https://docs.docker.com/desktop/setup/install/windows-install/)からCPUに適したDocker Desktopを導入し、起動します。

設定画面で次を確認します。項目名や表示の有無はDocker Desktopの版により異なります。

- General：Use WSL 2 based engineを有効化（既定で有効の場合もあります）
- Resources → WSL Integration：作業するUbuntuを有効化し、変更を適用
- Linuxコンテナを使用。Windowsコンテナへは切り替えない

Ubuntuのターミナルを開き、次を実行します。

```bash
docker version
docker info
docker compose version
```

ClientだけでなくServerの情報も表示されれば、Engineへ接続できています。dockerが見つからない場合はUbuntu側へaptで追加せず、Docker Desktopの起動状態とWSL Integrationを確認します。

## 4. GitとNode.jsの導入（Ubuntu）

ここからのbashコマンドはすべてUbuntuで実行します。

```bash
sudo apt update
sudo apt install -y git curl ca-certificates build-essential
```

Node.jsはUbuntu側に導入します。Microsoftの[WSL向けNode.js手順](https://learn.microsoft.com/en-us/windows/dev-environment/javascript/nodejs-on-wsl)で案内されるnvmなどを利用します。nvmの導入は同ページから参照される[公式の導入手順](https://github.com/nvm-sh/nvm#installing-and-updating)に従い、シェルを再起動した後に実行します。

```bash
nvm install --lts
nvm use --lts
node --version
npm --version
command -v node
command -v npm
```

このリポジトリのwp-envはNode.js 22.13.0以上を要求します。導入した版が満たすことを確認します。node・npmの実体が/mnt/c配下のWindows版を参照している場合は、Linux版を使うようPATHを確認します。

## 5. リポジトリの取得と起動（Ubuntu）

ソースはWindowsのCドライブやOneDrive配下ではなく、Ubuntuのホーム配下に置きます。Linuxツールを使う場合、同じLinuxファイルシステム内の配置が性能面でも推奨されています。[Microsoftの説明](https://learn.microsoft.com/en-us/windows/wsl/setup/environment)

```bash
mkdir -p ~/projects
cd ~/projects
git clone https://github.com/uemakm/wordpress_dev.git
cd wordpress_dev
npm ci
npm start
npm run seed
```

Mac側やWindows側のnode_modulesをコピーせず、Ubuntu側でnpm ciを実行します。文書の日本語名は維持します。Windowsのエディターで編集する場合はWSL対応機能などを使い、UTF-8で保存してください。

## 6. 動作確認

Windowsのブラウザで次を開きます。

- 開発サイト：http://localhost:8888/
- 管理画面：http://localhost:8888/wp-admin/
- テストサイト：http://localhost:8889/

ログインは[wp-env公式仕様](https://developer.wordpress.org/block-editor/reference-guides/packages/packages-env/)に記載された既定の検証用アカウントを使用します。

No.1〜No.30の記事、管理画面へのログイン、投稿・画像登録を確認します。Ubuntuでnpm stop → npm startを実行し、投稿や設定が保持されることも確認してください。npm run seedの再実行では既存記事をスキップします。

Windowsではまだ実測していないため、実施後にWindows・WSL・Ubuntu・Docker・Node.jsのバージョンと検証結果を記録してください。構築・検証記録にあるMacの実測値はWindowsの確認結果ではありません。

## 日常操作と問題の切り分け

通常はWindowsでDocker Desktopを起動し、Ubuntuで作業フォルダへ移動してnpm startを実行します。終了時はnpm stopを使います。

| 症状 | 確認すること |
| --- | --- |
| dockerコマンドなし・Engine接続不可 | Docker Desktopの起動、UbuntuのWSL Integration、Linuxコンテナモード |
| npmやファイル操作が遅い | ソースが/mnt/c配下にないか。~/projects配下へ再cloneする |
| node・npmがWindows版になる | command -vで参照先を確認し、Ubuntu側のnvmを有効化 |
| 8888・8889番を使用できない | 他のアプリを確認。必要なら個人用.wp-env.override.jsonでポート変更 |
| ブラウザで開けない | Ubuntuからcurl -I http://localhost:8888/で応答を確認。VPN・プロキシ・ファイアウォールも確認 |
| WSLの状態がおかしい | 作業を保存・コンテナを停止後、PowerShellでwsl --shutdownし、Docker DesktopとUbuntuを再起動 |

wsl --shutdownはほかのWSL作業も停止します。ファイアウォールの無効化やDBの初期化を通常の復旧手順にしないでください。ローカル検証用ポートはインターネットへ公開しません。
